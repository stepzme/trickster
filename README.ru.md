# Trickster

Trickster — проектный процесс создания нативных iOS-приложений с AI-ролями. Он проводит продукт от идеи и утверждённого описания до работающего дизайна, полной реализации и финальных материалов для публикации.

[English version](README.md)

## Версии

| Версия | Редакция | Статус | Отличие |
|---|---|---|---|
| `1.0.2` | Complex | Опубликована в npm | Детальный процесс: пять специализированных ролей и отдельные документы для scope, assets, app icon, store screenshots, реализации, проверки, acceptance и delivery. |
| `1.1.0` | Lite | Опубликована в npm | Упрощённый процесс: четыре роли, шесть стадий, меньше передач контекста, а один Designer отвечает за референсы, работающий MVP, графику и материалы для публикации. |
| `1.2.0` | Lite, несколько harness | Текущая версия репозитория; публикация в npm ожидается | Добавляет экспериментальный адаптер Claude Code к поддержке Codex и generic. Интеграция Claude Code сверена с официальной документацией, но ещё не прошла полный сквозной прогон в реальной сессии. |

Установка опубликованной редакции Lite из существующего Git- или Xcode-проекта:

```sh
npx @sgx22/trickster@1.1.0 init
```

После публикации `1.2.0` при необходимости можно явно выбрать harness:

```sh
npx @sgx22/trickster@1.2.0 init --harness codex
npx @sgx22/trickster@1.2.0 init --harness claude-code
npx @sgx22/trickster@1.2.0 init --harness generic
```

Для Claude Code команда `claude` должна быть доступна в `PATH`. Установщик добавляет управляемый импорт в корневой `CLAUDE.md`, не заменяя пользовательские инструкции. После установки начни новую сессию Claude Code и через `/context` проверь загрузку `trickster/AGENTS.md`. Поддержка остаётся экспериментальной до будущего полного прогона в реальной сессии.

Глобальная установка не поддерживается. После инициализации `trickster doctor --harness <name>` отдельно показывает корректность установки, локальные инструменты и возможности со статусом `VERIFY`, которые нужно проверить внутри agent-сессии. Наличие Markdown-файлов само по себе не подтверждает готовность всего iOS-пайплайна.

## Codex plugin

Клонируй этот репозиторий, открой его в терминале и установи локальный plugin:

```sh
codex plugin marketplace add .
codex plugin add trickster@trickster-local
```

Перезапусти Codex, открой проект приложения и попроси использовать `$trickster-ios`. Если это новая пустая папка, сначала выполни в ней `git init`. Skill установит собственную версионированную копию Trickster внутрь репозитория приложения; npm-installer 1.2.0 и экспериментальный адаптер Claude Code не обновляют snapshot плагина.

## Процесс Lite

`Research → Planning → Design → Dev → Polish → Publish`

- **Research:** описать полный продукт и принять решения по всем 11 iOS capabilities.
- **Planning:** разделить утверждённый продукт на дизайн-MVP и упорядоченные блоки Full Scope.
- **Design:** утвердить референсы, собрать MVP в Xcode и подтвердить реально запущенное приложение в Simulator.
- **Dev:** развить эту же сборку до Full Scope, подтверждая каждый крупный блок.
- **Polish:** независимо проверить завершённое приложение и провести точечные циклы исправлений.
- **Publish:** подготовить финальную app icon, store screenshots и экспортные материалы.

Поведение продукта определяется утверждёнными Research и Planning. Визуальное направление задают утверждённый `ui.md` и, при необходимости, `illustrations.md` из базы дизайна. Успешная сборка сама по себе не подтверждает дизайн — пользователь утверждает реально работающее приложение.

## Что устанавливается в проект

```text
trickster/
├── AGENTS.md
├── HARNESS
├── VERSION
├── adapters/
├── roles/
├── workflow/
├── templates/
├── design/
└── artifacts/
```

Полная база дизайна не входит в npm-пакет. Загружаются только документы, выбранные для текущего проекта. Повторная инициализация обновляет управляемые файлы процесса, сохраняя `design/` и `artifacts/`.

Требования: macOS, Xcode, Node.js 20+, подходящий iOS Simulator runtime и agent harness, умеющий использовать установленные инструкции. Для части финальных проверок нужен физический iPhone.
