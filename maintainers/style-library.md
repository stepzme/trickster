# Пополнение базы стилей

Это внутренняя инструкция для развития Trickster. Каталог `maintainers/` и библиотека `styles/` не входят в npm-пакет и не устанавливаются в пользовательские проекты. Screen Gallery используется только здесь как источник для подготовки пакетов в GitHub-репозитории.

## Результат для одного приложения

Создай папку `styles/<app-id>/` со следующими файлами:

- `source.json` — только `appId`, `url` и `category`;
- `ui.md` — визуальная система приложения по структуре `styles/_template/ui.md`;
- `ux.md` — краткое описание навигации, основных сценариев и характерных паттернов взаимодействия;
- `illustrations.md` — только если в просмотренных экранах есть выраженный иллюстративный язык.

Не создавай другие файлы и не добавляй дополнительные поля в `source.json`.

Добавь или обнови базовые поля приложения в `styles/catalog.json`: `appId`, `name`, `url` и `category`. Затем запусти:

```sh
node maintainers/build-style-catalog.mjs
```

Скрипт воспроизводимо добавляет metadata для shortlist из уже проверенных документов пакета:

- `categories` — нормализованные категории;
- `uiSummary` — описание из frontmatter `ui.md`;
- `uxSummary` — overview из `ux.md`;
- `navigationSummary` — навигационная модель из `ux.md`;
- `coreFlows` — названия реально просмотренных основных сценариев;
- `illustrationSummary` — описание иллюстративного языка или `null`.

Не заполняй эти производные поля вручную. Каталог является публичным индексом для пользовательского workflow; `source.json` внутри пакета остаётся внутренним минимальным provenance-файлом.

## Исследование

1. Используй Screen Gallery и установи точное приложение по app ID, а не по похожему названию.
2. Просмотри реальные изображения приложения и все доступные целые сценарии. Текстовое описание, поисковая выдача и метаданные не заменяют просмотр изображений.
3. Описывай только то, что видно на просмотренных экранах и в сценариях. Не додумывай скрытые состояния и поведение.
4. Если изображения или сценарии недоступны, не создавай пакет приложения и явно сообщи о блокировке.
5. При параллельной работе назначай каждому исполнителю отдельные приложения и разрешай запись только в их `styles/<app-id>/`.

## `source.json`

Используй точную структуру `styles/_template/source.json`. Не добавляй дату, версию, screen IDs, confidence, provenance или другие поля.

## `ui.md`

Используй `styles/_template/ui.md` как неизменную структуру результата:

- сохрани frontmatter и его разделы `colors`, `typography`, `rounded`, `spacing`, `components`;
- сохрани все разделы после frontmatter в том же порядке, что и в шаблоне;
- замени содержимое данными исследуемого приложения;
- в `components` описывай только характерные компоненты исследуемого приложения;
- не добавляй разделы сверх структуры шаблона, evidence maps, confidence labels, UX-аудит или универсальные рекомендации.

## `ux.md`

Используй короткую структуру `styles/_template/ux.md`. Описывай продуктовую навигацию, основные просмотренные сценарии и повторяющиеся паттерны взаимодействия. Не превращай файл в общий UX-чеклист и не перечисляй состояния, которых нет в доступных сценариях.

## `illustrations.md`

Создавай файл только тогда, когда иллюстрации действительно присутствуют в референсе. Используй структуру `styles/_template/illustrations.md` и описывай только их характер, композицию, цвет и применение.

Если иллюстраций в референсе нет, не создавай `illustrations.md`. Это не запрещает иллюстрации в продукте, который позже использует этот стиль: если они нужны продукту, агент должен создать оригинальный иллюстративный язык, гармонирующий с цветами, формами, типографикой и характером соответствующего `ui.md`.

## Самопроверка

Перед завершением проверь:

- папка названа точным app ID;
- `source.json` содержит ровно три согласованных поля;
- `catalog.json` содержит ровно одну запись с тем же app ID, названием, URL и категорией;
- `node maintainers/build-style-catalog.mjs --check` подтверждает соответствие enriched metadata документам пакетов;
- `ui.md` следует шаблону без новых разделов;
- `ux.md` остаётся кратким и основан на просмотренных сценариях;
- `illustrations.md` отсутствует, если у референса нет иллюстраций;
- пакет не содержит скопированных логотипов, текстов или готовых брендовых ассетов.
