# Этап 2. Выбор пакета стиля

## Цель

Предложить пользователю до трёх подходящих визуальных и поведенческих языков из локальной базы `trickster/styles/`, получить выбор ровно одного пакета и сделать его единственным дизайн-контекстом приложения.

## Состав пакета

Каждый пакет находится в `trickster/styles/<app-id>/` и содержит:

- `source.json` ровно с полями `appId`, `url`, `category`;
- `ui.md` с визуальной системой;
- `ux.md` с навигацией, основными сценариями и паттернами взаимодействия;
- `illustrations.md`, только если у референса есть выраженный иллюстративный язык.

Каталог `_template` не является кандидатом. Пакет считается полным, только если обязательные три файла существуют и не пусты, `appId` совпадает с именем каталога, а `source.json` содержит только указанные поля.

## Shortlist

1. Прочитай пользовательскую задачу, существующий проект и черновой scope в `product.md`.
2. Найди полные пакеты, подходящие по продуктовой задаче, категории, характеру интерфейса, плотности информации, иерархии и типу взаимодействия.
3. Если подходящих пакетов больше трёх, ранжируй их и оставь три лучших. Если их от одного до трёх, покажи все найденные.
4. Если точных совпадений нет, расширь поиск на всю локальную базу и предложи до трёх ближайших полных пакетов. Для каждого явно объясни компромисс и необходимую адаптацию к продукту.
5. Не выбирай пакет только потому, что его проще реализовать системными компонентами. Наличие или отсутствие `illustrations.md` само по себе не определяет выбор.

Для каждого варианта сообщи `appId`, URL и категорию; краткий характер стиля; почему он подходит; несколько конкретных визуальных или UX-приёмов; главное отличие от остальных кандидатов; существенные платформенные адаптации.

Если в библиотеке нет ни одного полного пакета, останови UI-работу и сообщи, что установка или база повреждена. Не создавай пакет по памяти и не переходи молча к стандартному нативному оформлению.

## Обязательный выбор пользователя

Попроси пользователя выбрать ровно один `appId` и останови проектирование UI до явного ответа.

- Если пользователь выбирает один пакет, подтверди выбор и переходи к фиксации.
- Если пользователь выбирает несколько пакетов или просит их объединить, отклони объединение и попроси оставить один.
- Можно сравнивать варианты и заменить выбор до начала реализации.
- Нельзя смешивать `ui.md`, `ux.md`, `illustrations.md`, цвета, компоненты или отдельные экраны из разных пакетов.
- Если пользователь отклоняет все варианты, уточни желаемый характер интерфейса и подготовь новый shortlist из локальной базы.

Shortlist не является набором параллельных дизайн-концепций: после выбора реализуется только один пакет.

## Фиксация после выбора

После подтверждения скопируй выбранный пакет без изменения содержания в:

```text
trickster/design/source.json
trickster/design/ui.md
trickster/design/ux.md
trickster/design/illustrations.md          # только если есть в пакете

trickster/artifacts/<run-id>/inputs/style/source.json
trickster/artifacts/<run-id>/inputs/style/ui.md
trickster/artifacts/<run-id>/inputs/style/ux.md
trickster/artifacts/<run-id>/inputs/style/illustrations.md  # только если есть
```

Не комбинируй файлы разных пакетов. Если новый пакет не содержит `illustrations.md`, удали оставшийся от предыдущего выбора рабочий `trickster/design/illustrations.md`. Snapshot внутри run-id неизменяем и является источником конкретного запуска. Shortlist и подтверждение пользователя фиксируются в `product.md` и `review.md`; `source.json` остаётся минимальным.
