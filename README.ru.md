# Trickster

### AI-фабрика нативных iOS-приложений.

Превращает идею приложения в нативный iOS-продукт на основе курируемой дизайн-базы: определяет scope, добавляет фиксированный набор iOS capabilities, проектирует, реализует, проверяет и завершает результат оригинальной app icon и ASO-скриншотами.

Trickster оркестрирует специализированные AI-роли внутри репозитория. Он читает небольшой GitHub-каталог, загружает документы максимум трёх релевантных стилей, требует выбрать ровно один, сохраняет его в проекте и независимо проверяет реализованный результат.

## Что получается на выходе

- работающий Xcode-проект и нативное iOS-приложение;
- продуктовый scope, основанный на задании и существующем проекте;
- одна связанная с продуктом функция для каждой из одиннадцати обязательных iOS capabilities;
- один подтверждённый визуальный язык, локально сохранённый после выбора из GitHub-каталога;
- стилизованные контролы, сохраняющие нативное поведение и доступность iOS;
- доказательства сборки, запуска, взаимодействия и визуальной проверки в Simulator;
- одна оригинальная app icon по просмотренным Logoinspo-референсам;
- один ASO-комплект из экранов принятой сборки.

## Пайплайн

```text
Идея приложения
→ продуктовый scope
→ обязательные iOS capabilities
→ shortlist по GitHub-каталогу
→ выбор одного стиля
→ нативная реализация
→ приёмка в Simulator
→ app icon и ASO-скриншоты
```

1. **Определение продукта.** Фиксируются запрошенный scope, границы и решения, которые действительно требуют ответа пользователя.
2. **Адаптация обязательных iOS capabilities.** Независимо от scope промпта агент придумывает осмысленную продуктовую функцию для каждого из одиннадцати пунктов фиксированного списка.
3. **Сравнение релевантных стилей.** Агент читает GitHub-каталог, выбирает по метаданным до трёх кандидатов и загружает документы только для них.
4. **Выбор одного направления.** До начала UI-работы пользователь обязан выбрать ровно один пакет. Пакеты нельзя объединять или распределять по разным экранам.
5. **Контракт продукта.** Фиксируются экраны, состояния, capability-сценарии, ассеты и проверки приёмки.
6. **Реализация приложения.** Сначала создаётся и визуально проверяется один вертикальный сценарий, затем выполняются весь согласованный scope и все одиннадцать capability-функций.
7. **Независимая проверка.** Финальное приложение собирается, устанавливается, запускается и проверяется в Simulator и на физическом iPhone там, где это обязательно. Недоступные доказательства остаются `UNVERIFIED`.
8. **Store package.** Создаётся оригинальная app icon, а после приёмки — ASO-скриншоты из реальной сборки.

Если выбранный agent harness поддерживает делегирование, Trickster использует несколько сфокусированных ролей. В другой среде те же контракты выполняются последовательно.

## Быстрый старт

Запусти из корня существующего Git-, Xcode-, Swift Package- или XcodeGen-проекта:

```sh
npx @sgx22/trickster init
```

По умолчанию используется Codex adapter. Проверь локальную установку:

```sh
npx @sgx22/trickster doctor
```

После этого создай новую задачу для агента и вставь бриф по этому шаблону:

```text
Используя Trickster, создай или существенно измени нативное iOS-приложение.

Идея:
Пользователь:
Основная задача:
Обязательные функции:
Вне текущего scope:
Ограничения:
```

Описание может быть коротким. Пользователю не нужно перечислять системные возможности: Trickster автоматически адаптирует фиксированный набор из одиннадцати iOS capabilities, при необходимости уточнит один пробел, влияющий на границы продукта, и попросит выбрать один пакет стиля до начала работы над UI. Установленные project instructions активируют обязательные capability-, дизайн- и acceptance-gates.

## Обязательные iOS capabilities

Каждое новое или существенно изменяемое приложение должно включать осмысленную продуктовую функцию для каждого пункта строго в этом порядке:

1. Bluetooth
2. Скачивание фото
3. Добавление фото
4. Использование камеры
5. Face ID
6. Доступ к микрофону
7. Доступ к распознаванию речи
8. Доступ к контактам
9. Доступ к календарю
10. Доступ к геолокации
11. CallKit

Агент не может пропустить, объединить, переименовать, переставить, заменить или пометить пункт `N/A`. Кнопка, которая только вызывает permission prompt, фальшивое устройство или фальшивый звонок не считаются реализацией: у каждой функции должны быть контекстная точка входа, полезный результат, обработка отказа или недоступности и воспроизводимое доказательство. System picker или capability без обычного permission prompt остаются в списке и реализуются через корректный механизм iOS.

Для другого agent harness:

```sh
npx @sgx22/trickster init --harness generic
```

Сопоставь операции оркестрации со своей средой по `trickster/adapters/generic.md`.

## Как устроена установка

Trickster устанавливается внутрь текущего проекта, а не глобально:

```text
trickster/
├── AGENTS.md
├── HARNESS
├── roles/
├── adapters/
├── workflow/
├── templates/
├── design/
└── artifacts/
```

- `design/` содержит единственный пакет стиля, подтверждённый для текущего продукта.
- `artifacts/<run-id>/` содержит контракты, доказательства, скриншоты и результаты проверки.
- `roles/` и `workflow/` задают этапы фабрики независимо от конкретного agent harness.
- `adapters/` связывают эти этапы с Codex или другой средой.

Повторный `init` обновляет управляемые документы процесса, сохраняя выбранный дизайн и run artifacts.

## Источники дизайна

- **GitHub-каталог стилей** перечисляет доступные приложения-референсы. Trickster загружает документы только для shortlist, а выбранные `source.json`, `ui.md`, `ux.md` и опциональный `illustrations.md` сохраняет в `trickster/design/`.
- **Logoinspo App Icons** используется как источник референсов для оригинального направления app icon.

Пакет стиля — не просто смена палитры. Нативные контролы могут обеспечивать поведение, доступность, focus и работу с клавиатурой, но их внешний вид должен явно наследовать `ui.md`, когда референс задаёт собственный визуальный язык.

## Подробные этапы

| Этап | Владелец | Обязательный результат |
|---|---|---|
| 1. Scope | product-researcher | Явный статус scope и недостающие решения |
| 2. Обязательные iOS capabilities | product-researcher + gate мастера | Одиннадцать продуктовых функций в фиксированной матрице |
| 3. Выбор стиля | design-planner + подтверждение пользователя | До трёх кандидатов из GitHub и ровно один локально сохранённый пакет |
| 4. Контракт продукта | design-planner | Экраны, состояния, сценарии, ассеты и план проверки |
| 5. Продуктовые ассеты | visual-producer при необходимости | Проверенные изображения или обоснованный `N/A` |
| 6. Реализация | implementation-owner | Вертикальный сценарий, полный согласованный scope и capabilities |
| 7. App icon | visual-producer | Одна оригинальная концепция, установленная в приложение |
| 8. Приёмка | acceptance-reviewer + master | Независимо проверенная сборка и capability-матрица |
| 9. ASO screenshots | visual-producer | Один комплект из реальных экранов принятой сборки |
| 10. Финализация | master + подтверждение пользователя | Явное подтверждение результата и очистка временных файлов |
| 11. Передача | master | Воспроизводимые доказательства и итоговый статус |

Точные правила исполнения находятся в [главном процессе](workflow/master-prompt.md) и [контракте оркестрации](workflow/orchestration.md).

## Основные гарантии

- Shortlist содержит не более трёх пакетов, выбранных по метаданным каталога; загружаются документы только этих кандидатов.
- Все одиннадцать канонических iOS capabilities входят в контракт и реализацию независимо от scope промпта; ни одну нельзя пометить `N/A`.
- UI не реализуется, пока пользователь не выбрал ровно один пакет.
- Пакеты нельзя объединять: выбранный пакет становится единственным дизайн-контекстом.
- Нативное поведение контролов сохраняется, но внешний вид следует выбранному визуальному языку.
- Исполнитель реализации не может сам принять свою работу.
- Успешная сборка сама по себе не является приёмкой.
- Недоступные инструменты и доказательства помечаются `UNVERIFIED`, а не подменяются предположениями.

## Требования и границы

Для Trickster нужны macOS, Xcode, подходящий iOS Simulator runtime, физический iPhone и необходимые периферийные устройства для обязательной проверки hardware-dependent capabilities, Node.js 20 или новее и агентная среда, способная читать установленные инструкции и работать с инструментами проекта. Для нового выбора стиля нужен доступ к raw-файлам GitHub-репозитория Trickster; существующий проект продолжает использовать локально сохранённый пакет.

Подписание для capability-проверки на физическом устройстве входит в приёмку. Release archive, публикация в App Store и production deployment остаются отдельными задачами выпуска. Требуемый capability реальный внешний сервис должен быть подключён или отмечен `UNVERIFIED`.

Глобальная установка намеренно запрещена. Используй `npx` как временный launcher внутри целевого проекта.
