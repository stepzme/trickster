# Trickster

### AI-фабрика нативных iOS-приложений.

Превращает идею приложения в нативный iOS-продукт с дизайном на основе реальных референсов: исследует, проектирует, реализует, проверяет в Simulator и завершает результат оригинальной app icon и ASO-скриншотами.

Trickster оркестрирует специализированные AI-роли внутри репозитория. Он изучает реальные продукты до проектирования, просит подтвердить одно визуальное направление, реализует приложение и независимо проверяет результат, а не считает сгенерированный код готовым продуктом.

## Что получается на выходе

- работающий Xcode-проект и нативное iOS-приложение;
- продуктовый scope, основанный на реальных приложениях той же категории;
- один подтверждённый визуальный язык из локальной базы стилей Screen Gallery;
- стилизованные контролы, сохраняющие нативное поведение и доступность iOS;
- доказательства сборки, запуска, взаимодействия и визуальной проверки в Simulator;
- одна оригинальная app icon по просмотренным Logoinspo-референсам;
- один ASO-комплект из экранов принятой сборки.

## Пайплайн

```text
Идея приложения
→ продуктовый scope
→ реальные UI-референсы
→ подтверждение стиля
→ нативная реализация
→ приёмка в Simulator
→ app icon и ASO-скриншоты
```

1. **Исследование продукта.** Определяется запрошенный scope; при неполном задании восстанавливается разумный baseline категории.
2. **Изучение реальных интерфейсов.** Просматриваются релевантные экраны и целые сценарии Screen Gallery — дизайн не создаётся по памяти.
3. **Подтверждение одного направления.** Выбирается один локальный пакет стиля, после чего процесс останавливается до явного подтверждения пользователя.
4. **Контракт продукта.** Фиксируются экраны, состояния, сценарии, ассеты и проверки приёмки.
5. **Реализация приложения.** Сначала создаётся и визуально проверяется один вертикальный сценарий, затем выполняется весь согласованный scope.
6. **Независимая проверка.** Финальное приложение собирается, устанавливается, запускается и проверяется в Simulator. Недоступные доказательства остаются `UNVERIFIED`.
7. **Store package.** Создаётся оригинальная app icon, а после приёмки — ASO-скриншоты из реальной сборки.

Если выбранный agent harness поддерживает делегирование, Trickster использует несколько сфокусированных ролей. В другой среде те же контракты выполняются последовательно.

## Быстрый старт

Запусти из корня существующего Git-, Xcode-, Swift Package- или XcodeGen-проекта:

```sh
npx @sgx22/trickster init
```

По умолчанию используется Codex adapter. При необходимости авторизуй Screen Gallery:

```sh
codex mcp login screen_gallery
```

Проверь локальную установку:

```sh
npx @sgx22/trickster doctor
```

После этого попроси агента создать или существенно изменить iOS-приложение через Trickster. Установленные project instructions активируют пайплайн и обязательные этапы подтверждения дизайна и приёмки.

Для другого agent harness:

```sh
npx @sgx22/trickster init --harness generic
```

Подключи Screen Gallery и сопоставь операции оркестрации со своей средой по `trickster/adapters/generic.md`.

## Как устроена установка

Trickster устанавливается внутрь текущего проекта, а не глобально:

```text
trickster/
├── AGENTS.md
├── HARNESS
├── roles/
├── adapters/
├── workflow/
├── templates/
├── styles/
├── design/
└── artifacts/
```

- `styles/` содержит переиспользуемые пакеты референсных приложений Screen Gallery.
- `design/` содержит пакет стиля, подтверждённый для текущего продукта.
- `artifacts/<run-id>/` содержит неизменяемые входы, контракты, доказательства, скриншоты и результаты проверки.
- `roles/` и `workflow/` задают этапы фабрики независимо от конкретного agent harness.
- `adapters/` связывают эти этапы с Codex или другой средой.

Повторный `init` обновляет управляемые документы процесса и поставляемую базу стилей, сохраняя выбранный дизайн и run artifacts.

## Источники дизайна

- **Screen Gallery MCP** предоставляет реальные экраны и сценарии для исследования продукта и UX.
- **Локальная база стилей** предоставляет `source.json`, `ui.md`, `ux.md` и опциональный `illustrations.md` для каждого приложения-референса.
- **Logoinspo App Icons** используется как источник референсов для оригинального направления app icon.

Пакет стиля — не просто смена палитры. Нативные контролы могут обеспечивать поведение, доступность, focus и работу с клавиатурой, но их внешний вид должен явно наследовать `ui.md`, когда референс задаёт собственный визуальный язык.

## Подробные этапы

| Этап | Владелец | Обязательный результат |
|---|---|---|
| 1. Scope | product-researcher | Явный статус scope и недостающие решения |
| 2. Исследование экранов | product-researcher | Просмотренные изображения, релевантная категория и baseline при необходимости |
| 3. Пакет стиля | design-planner + подтверждение пользователя | Один локальный пакет и явное подтверждение |
| 4. Контракт продукта | design-planner | Экраны, состояния, сценарии, ассеты и план проверки |
| 5. Продуктовые ассеты | visual-producer при необходимости | Проверенные изображения или обоснованный `N/A` |
| 6. Реализация | implementation-owner | Вертикальный сценарий и полный согласованный scope |
| 7. App icon | visual-producer | Одна оригинальная концепция, установленная в приложение |
| 8. Приёмка | acceptance-reviewer + master | Независимо проверенная финальная сборка |
| 9. ASO screenshots | visual-producer | Один комплект из реальных экранов принятой сборки |
| 10. Передача | master | Воспроизводимые доказательства и итоговый статус |

Точные правила исполнения находятся в [главном процессе](workflow/master-prompt.md) и [контракте оркестрации](workflow/orchestration.md).

## Основные гарантии

- Визуальные выводы требуют просмотра реальных изображений референса.
- UI не реализуется до подтверждения одного визуального направления пользователем.
- Пайплайн создаёт одно связное решение, а не набор альтернатив.
- Нативное поведение контролов сохраняется, но внешний вид следует выбранному визуальному языку.
- Исполнитель реализации не может сам принять свою работу.
- Успешная сборка сама по себе не является приёмкой.
- Недоступные инструменты и доказательства помечаются `UNVERIFIED`, а не подменяются предположениями.

## Требования и границы

Для Trickster нужны macOS, Xcode, подходящий iOS Simulator runtime, Node.js 20 или новее и агентная среда, способная читать установленные инструкции и работать с инструментами проекта. Для исследования референсов необходим доступ к Screen Gallery.

Подписание, release archive, проверка на физическом устройстве, публикация в App Store и внешняя production-инфраструктура остаются отдельными задачами выпуска, если явно не включены в scope.

Глобальная установка намеренно запрещена. Используй `npx` как временный launcher внутри целевого проекта.
