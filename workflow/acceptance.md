# Приёмка приложения

До реализации главный агент фиксирует применимость критериев и сценарии в product.md. Критерии не ослабляются для оправдания готовой реализации.

## Статусы отдельных проверок

- PASS — выполнена проверка, результат соответствует ожиданию, доказательство доступно.
- FAIL — наблюдалось нарушение критерия.
- UNVERIFIED — данных, инструмента или выполнения проверки не хватает.
- N/A — неприменимо, указана проверяемая причина. Обязательные критерии не могут быть N/A.

## Критерии

| ID | Критерий | Доказательство | Применимость |
|---|---|---|---|
| AC-01 | Итоговый код собирается средствами Xcode | Команда, код завершения, полный лог, ревизия | Обязательно |
| AC-02 | Именно эта сборка устанавливается и запускается в Simulator | Устройство/OS, bundle ID, команды и скриншот запущенного приложения | Обязательно |
| AC-03 | Все обязательные сценарии product.md дают ожидаемый результат | Шаги/утверждения UI-тестов, наблюдаемый результат и данные | Обязательно |
| AC-04 | Экраны последовательно выражают выбранный стиль | Актуальные скриншоты, просмотренные референсы и разбор характерных признаков | Обязательно |
| AC-05 | Вёрстка и текст сохраняют функции на целевых размерах | Скриншоты основного и компактного поддерживаемого iPhone, большого текста | Обязательно |
| AC-06 | Выполнены применимые UX-01…UX-12 | Поэкранная матрица правил и фактических наблюдений | Обязательно |
| AC-07 | Сохранение данных переживает перезапуск | Создание/изменение данных → перезапуск → проверка значений | Если продукт хранит данные |
| AC-08 | Ошибки и ограничения не ломают обязательный сценарий | Проверенные ошибки сети/ввода/разрешений по контракту | Если применимо |
| AC-09 | Обещанные локали, темы, ориентации и iPad поддержаны | Проверка объявленной в product.md матрицы | Если объявлены |
| AC-10 | Все доказательства соответствуют итоговой версии | Ревизия, время сборки, среда и перечень артефактов | Обязательно |

Скриншот показывает внешний вид и состояние; он не доказывает сохранение данных или корректность переходов. Для поведения нужны действия и проверка результата. Сгенерированные макеты не заменяют скриншоты из Simulator.

## Решение

- ACCEPTED — все обязательные и применимые критерии PASS, остальные обоснованно N/A; открытых дефектов по ним нет.
- NEEDS_WORK — есть хотя бы один FAIL. Непроверенные пункты перечисляются дополнительно.
- UNVERIFIED — FAIL не обнаружен, но хотя бы один необходимый пункт не проверен.

Визуальный PASS — суждение агента по заданным ориентирам; его надёжность оценивается пилотом. Он не доказывает рыночную успешность дизайна.

## Отдельный выпуск

ACCEPTED относится к согласованному объёму разработки и проверки в Simulator. Подписывание, релизный архив, реальные устройства и публикация входят в отдельную задачу выпуска. Не публикуй приложение без поручения пользователя.
