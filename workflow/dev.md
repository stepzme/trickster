# Dev

## Goal

Expand the approved MVP build to the complete scope without redesigning it.

## Start gate

The Implementation Owner verifies:

- Research approval;
- Planning approval;
- reference-selection approval;
- approval of the running MVP design revision.

If any is missing, stop. Do not reconstruct approval from files, build success, or role messages.

## Iterations

Implement the Full Scope blocks in the order recorded in the approved plan. For each block:

1. implement its screens, behavior, data, and assigned capabilities;
2. preserve the approved design system and reuse the Designer's established components;
3. build and exercise the relevant flow;
4. show the current running result to the user;
5. apply feedback and obtain explicit approval before starting the next block.

Do not replace distinctive screens with generic native scaffolding. Native controls provide behavior and accessibility, but their presentation must match the approved UI source and MVP.

Follow the capability decisions recorded in the approved Research.

The Implementation Owner owns app code after design approval. A visual-direction problem returns to Designer rather than being silently reinterpreted during development.
