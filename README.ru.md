# Trixter

Trixter — проектная AI-команда для разработки нативных iOS-приложений. Четыре роли проводят продукт от идеи и работающего дизайна до полной реализации, независимой проверки и материалов для публикации.

[English version](README.md)

## Версии

| Версия | Редакция | Статус | Отличие |
|---|---|---|---|
| `1.0.2` | Trickster Complex | Опубликована как `@sgx22/trickster` | Детальный процесс с пятью специализированными ролями и отдельными документами поставки. |
| `1.1.0` | Trickster Lite | Опубликована как `@sgx22/trickster` | Четыре роли, шесть стадий и меньше передач контекста. |
| `2.0.0` | Trixter | Текущая версия репозитория; публикация в npm ожидается | Переименовывает продукт и технические идентификаторы, добавляет несколько harness и переносит существующие установки `trickster/` без потери дизайн-источников и артефактов. |

До публикации 2.0 установите существующую редакцию Lite из Git- или Xcode-проекта:

```sh
npx @sgx22/trickster@1.1.0 init
```

В Trixter 2.0 при необходимости можно явно выбрать harness:

```sh
npx @sgx22/trixter@2.0.0 init --harness codex
npx @sgx22/trixter@2.0.0 init --harness claude-code
npx @sgx22/trixter@2.0.0 init --harness generic
```

Для Claude Code команда `claude` должна быть доступна в `PATH`. Установщик добавляет управляемый импорт в корневой `CLAUDE.md`, не заменяя пользовательские инструкции. После установки начни новую сессию Claude Code и через `/context` проверь загрузку `trixter/AGENTS.md`. Поддержка остаётся экспериментальной до будущего полного прогона в реальной сессии.

Глобальная установка не поддерживается. После инициализации `trixter doctor --harness <name>` отдельно показывает корректность установки, локальные инструменты и возможности со статусом `VERIFY`, которые нужно проверить внутри agent-сессии. Наличие Markdown-файлов само по себе не подтверждает готовность всего iOS-пайплайна.

## Codex plugin

Клонируй этот репозиторий, открой его в терминале и установи локальный plugin:

```sh
codex plugin marketplace add .
codex plugin add trixter@trixter-local
```

Перезапусти Codex, открой проект приложения и попроси использовать `$trixter-ios`. Если это новая пустая папка, сначала выполни в ней `git init`. Skill устанавливает собственную версионированную копию Trixter внутрь репозитория приложения; npm-installer и snapshot плагина версионируются независимо.

## Совместимость при переименовании

Trixter 2.0 распознаёт существующую установку `trickster/` и переносит её в `trixter/` до обновления управляемых файлов. Пользовательские `design/` и `artifacts/` сохраняются. Если в проекте уже существуют обе папки, установка останавливается и не пытается угадать, какие данные оставить. В репозитории также подготовлен исходник устаревшего пакета совместимости `@sgx22/trickster`, который после публикации 2.0 будет передавать старую команду новому `@sgx22/trixter`.

## Процесс Lite

`Research → Planning → Design → Dev → Polish → Publish`

- **Research:** описать полный продукт и принять решения по всем 11 iOS capabilities.
- **Planning:** разделить утверждённый продукт на дизайн-MVP и упорядоченные блоки Full Scope.
- **Design:** утвердить референсы, собрать MVP в Xcode и подтвердить реально запущенное приложение в Simulator.
- **Dev:** развить эту же сборку до Full Scope, подтверждая каждый крупный блок.
- **Polish:** независимо проверить завершённое приложение и провести точечные циклы исправлений.
- **Publish:** подготовить финальную app icon, store screenshots и экспортные материалы.

Поведение продукта определяется утверждёнными Research и Planning. Визуальное направление задают утверждённый `ui.md` и, при необходимости, `illustrations.md` из базы дизайна. Успешная сборка сама по себе не подтверждает дизайн — пользователь утверждает реально работающее приложение.

## Что устанавливается в проект

```text
trixter/
├── AGENTS.md
├── HARNESS
├── VERSION
├── adapters/
├── roles/
├── workflow/
├── templates/
├── design/
└── artifacts/
```

Полная база дизайна не входит в npm-пакет. Загружаются только документы, выбранные для текущего проекта. Повторная инициализация обновляет управляемые файлы процесса, сохраняя `design/` и `artifacts/`.

Требования: macOS, Xcode, Node.js 20+, подходящий iOS Simulator runtime и agent harness, умеющий использовать установленные инструкции. Для части финальных проверок нужен физический iPhone.
