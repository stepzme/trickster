# Trickster — процесс разработки и дизайн-ревью iOS-приложений

Версия комплекта: 0.1, пилот. Общие правила процесса; визуальное направление выбирается отдельно для каждого приложения.

## Что уже подготовлено

- [Мастер-промпт](workflow/master-prompt.md): главный агент делегирует реализацию и принимает результат.
- [Правила UX](workflow/ux.md) и [критерии приёмки](workflow/acceptance.md).
- [Каталог стилей](styles/index.md) и [шаблон design.md](styles/_template/design.md).
- [Шаблон описания приложения](templates/product.md) и [отчёта](templates/review.md).
- [Требования к среде iOS](workflow/ios.md).
- [План пилота](workflow/pilot.md).

Стилей с визуальными примерами пока нет. Полный цикл разработки, запуска и визуального ревью ещё не проверен. Markdown задаёт поведение агента, но не устанавливает инструменты и не гарантирует выполнение проверок.

## Как подключить к приложению

1. Скопировать папки `workflow`, `styles`, `templates` в репозиторий приложения. Зафиксировать версию комплекта в Git.
2. Добавить инструкции из [AGENTS.md](AGENTS.md) в существующий корневой файл проекта, сохранив его текущие правила. В Codex этот файл служит точкой входа. В другом агенте явно подключить мастер-промпт через его механизм инструкций.
3. Проверить среду по [ios.md](workflow/ios.md). В новом сеансе убедиться, что агент прочитал правила и действительно имеет инструменты делегирования, взаимодействия с симулятором и просмотра изображений.
4. Отправить обычное задание. Остальную документацию проекта и доказательства проверки создаёт агент.

Пример задания после наполнения каталога:

> Сделай iOS-приложение для [аудитория], которое помогает [задача]. Основные функции: [список]. Используй стиль [ID] либо подбери подходящий из каталога. Выполни процесс из workflow/master-prompt.md до проверяемого результата.

## Что сделать дальше

Выбрать среду агента, добавить первые 2–3 стиля с аннотированными экранами, подготовить Simulator и провести пилот на одном небольшом приложении. Настройка инструментов и пилот выполняются один раз; разработчик не должен вручную обслуживать внутренние этапы каждого запуска.
