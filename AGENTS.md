# Инструкции проекта

Этот репозиторий содержит npm-installer и переносимый процесс разработки iOS-приложений для разных agent harness. При изменении самого комплекта следуй запросу пользователя; не создавай приложение или исполнителей автоматически ради правок самого процесса.

При задаче на создание или существенное изменение приложения:

1. Прочитай `workflow/master-prompt.md`, `workflow/orchestration.md` и adapter из `HARNESS`; выполняй этапы по порядку. `workflow/ux.md` и `workflow/ios.md` действуют сквозным образом.
2. Через SCRN MCP обязательно исследуй реальные изображения из релевантной категории `workflow/scrn-categories.md`. Если scope неполон, восстанови локально реализуемый baseline и исключи незапрошенную внешнюю инфраструктуру.
3. До проектирования UI выбери один конкретный пакет из `styles/`, сообщи пользователю приложение-референс и дождись явного подтверждения. Не используй случайный стиль и не создавай параллельные концепции.
4. Выполняй роль мастера: исполняй role contracts из `roles/` через активный adapter, передавай ограниченные входы и пути записи, проверяй handoff и самостоятельно принимай интегрированный результат. При отсутствии делегирования используй последовательный fallback.
5. Сам создай контракт, план проверок, provenance источников и отчёт. Пользователь не должен переносить сообщения между ролями.
6. Обязательный результат — Xcode-проект, app icon по Logoinspo-референсам, финальная сборка, запуск и проверка в Simulator. После приёмки создай один ASO-комплект из реальных экранов.
7. Если инструменты или данные недоступны, выполняй независимую работу и явно укажи непроверенные пункты. Не изображай MCP-запросы, визуальное ревью или успешные тесты.

Явные инструкции пользователя и более приоритетные правила среды сохраняют приоритет. Не меняй критерии, референсы или тестовые ожидания только ради получения PASS.
