THE DIFFERENCE

AI can write the app.
Trickster makes the process accountable.

It installs a production workflow inside your repository: explicit gates, focused roles, local evidence, and a definition of done that goes beyond a successful compile.

A TYPICAL AGENT RUN

  1. 01Interpret a loose brief
  2. 02Choose a look implicitly
  3. 03Generate many files
  4. 04Report “build succeeded”

Result: plausible, not proven.

A TRICKSTER RUN

  1. 01Approve the complete product
  2. 02Approve the MVP and delivery blocks
  3. 03Approve the running design
  4. 04Build and approve each full-scope block

Result: a reviewable product.

THE CONTROLLED PIPELINE

Six stages.
No invisible leaps.

Each stage ends with an approved artifact or a working app revision. A successful compile never substitutes for design approval.

01

RESEARCH

Define the complete product

Describe the whole product and the contextual use of all eleven iOS capabilities.

Output → Approved product description
02

PLANNING

Choose the first review surface

Split the approved product into a focused design MVP and ordered Full Scope blocks.

Output → Approved implementation plan
03

DESIGN

Prove the design in code

Approve source references, then let the Designer implement and run the MVP in Simulator.

Output → Approved running MVP
04

DEV

Expand without redesigning

Implement one Full Scope block at a time and approve its running result before continuing.

Output → Approved complete scope
05

POLISH

Verify and refine

Independently verify the completed app and retest concrete defect batches until it is ready.

Output → Approved polished app
06

PUBLISH

Create final materials

Create the final app icon, real store screenshots, and a complete publication export set.

Output → Approved publication materials

NON-NEGOTIABLES

The workflow holds the line.

Constraints are features when the alternative is an impressive-looking result nobody truly checked.

01

One style means one style.

Packages are never merged across screens, and implementation pauses until you select the direction.

02

Native behavior stays native.

Custom appearance must preserve accessibility, focus, keyboard integration, and platform behavior.

03

No self-acceptance.

The implementation owner cannot approve their own work. Evidence is independently reviewed.

04

Missing checks stay explicit.

If a device, service, or tool is unavailable, the review states exactly what was not checked.
