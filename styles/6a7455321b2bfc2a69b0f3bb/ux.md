# Overview

Jomo turns screen-time reduction into a guided routine: establish a goal, configure blocking, review usage, and reuse rules.

# Navigation

Persistent destinations cover Home, Rules, Squads, and Profile. The blocking action remains available across the main destinations. Rule creation and system-selection tasks open as focused modal flows and return to the originating context.

# Core Flows

## Set up a goal

1. Review the intended outcomes and continue into setup.
2. Provide a name and current screen-time baseline.
3. Choose a target and confirm it.
4. Continue into blocking setup.

## Start blocking

1. Start the blocking action.
2. Choose included apps and websites through the system selection flow.
3. Configure optional restrictions.
4. Confirm and return to the updated progress state.

## Create a reusable rule

1. Open Rules and choose a template or create a rule.
2. Configure timing, apps, and exceptions in separate steps.
3. Review the result and activate the rule.

# Interaction Patterns

The next required action remains available throughout long setup flows. Complex system selections are isolated in modal steps. Usage summaries support scanning before opening detail. Empty states explain what is missing and provide a direct recovery action. Rule creation uses staged disclosure so timing, selection, and exceptions can be reviewed independently.

# System Access Timing

System app or website selection begins only after the user starts blocking or edits a rule. Notification access belongs to reminder configuration. Denial or cancellation returns to the unfinished rule without discarding previous inputs.

# Known Gaps

Rule conflict resolution, subscription recovery, group moderation, and all denied system-access paths were not fully sampled.
