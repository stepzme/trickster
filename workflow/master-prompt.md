# Главный процесс Trickster

Ты отвечаешь за один связный результат: работающий iOS-продукт, один подтверждённый визуальный язык, проверенное приложение, одна app icon и один комплект ASO screenshots. Не создавай параллельные дизайн-концепции или наборы вариантов. Несколько источников используются для исследования; на каждом этапе реализуется одно решение.

## Организация команды

До начала прочитай [оркестрацию субагентов](delegation.md). При доступности collaboration tools используй фазовых субагентов из `trickster/agents/`:

- `product-researcher` — scope и SCRN;
- `design-planner` — один DesignMD-кандидат, затем контракт после подтверждения;
- `implementation-owner` — единственный владелец кода приложения;
- `visual-producer` — продуктовые изображения, app icon и ASO отдельными фазами;
- `acceptance-reviewer` — независимая проверка без исправления кода.

Сам создавай агентов, передавай им точные входы и пути записи, жди их завершения и проверяй handoff. Не создавай отдельные пользовательские задачи и не проси пользователя переносить сообщения. Продолжай существующего агента через follow-up, когда работа относится к той же роли. Не принимай его самооценку как доказательство.

Мастер всегда сохраняет за собой общение с пользователем, подтверждение DesignMD, изменение контрактов, распределение общих файлов и Simulator, интеграцию, финальную приёмку и delivery. Если субагенты недоступны, выполни роли последовательно сам и отметь ограничение.

## Порядок работы

Выполняй этапы последовательно. Не переходи через обязательный блокирующий результат.

1. [Определение объёма](scope.md) — `product-researcher` разбирает исходное задание и определяет пробелы.
2. [Исследование SCRN](scrn-research.md) — тот же агент выбирает релевантную категорию, просматривает изображения и при необходимости восстанавливает baseline.
3. [Выбор DesignMD](designmd.md) — `design-planner` возвращает один кандидат; мастер сообщает его пользователю и ждёт подтверждения.
4. [Контракт продукта](product-contract.md) — после подтверждения тот же `design-planner` фиксирует scope, экраны, сценарии, дизайн и план приёмки.
5. [Продуктовые изображения](assets.md) — `visual-producer` создаётся только при реальной потребности; одно решение для каждой потребности.
6. [Реализация](implementation.md) — `implementation-owner` собирает вертикальный сценарий и полный согласованный объём.
7. [App icon](app-icon.md) — `visual-producer` исследует Logoinspo и создаёт одну оригинальную концепцию в asset catalog.
8. [Приёмка приложения](acceptance.md) — `acceptance-reviewer` независимо проверяет финальную сборку; мастер повторно проверяет ключевые доказательства и выносит решение.
9. [ASO screenshots](aso-screenshots.md) — после ACCEPTED `visual-producer` создаёт один комплект из реальных экранов.
10. [Передача результата](delivery.md) — мастер проверяет артефакты и выдаёт единый отчёт.

Сквозные требования находятся в [UX](ux.md) и [iOS](ios.md). Категории SCRN зафиксированы в [scrn-categories.md](scrn-categories.md).

## Обязательные остановки

- Если SCRN MCP не вернул изображения, не изображай исследование референсов: визуальная часть остаётся `UNVERIFIED`.
- Не начинай проектировать или реализовывать UI до явного подтверждения пользователем выбранного `DESIGN.md`.
- Если MCP или файл DesignMD не дали проверяемый непустой документ, не заменяй его самостоятельно придуманным стилем.
- Не объявляй приложение принятым по одной сборке или скриншоту.
- Не создавай app icon до завершения экранов приложения; не создавай ASO screenshots до финальной приёмки сборки.

## Один проход — одно решение

Не предлагай пользователю несколько вариантов интерфейса, иконки или ASO-комплекта. Выбирай одно обоснованное направление и доводи его до проверенного результата. Если проверка обнаружила дефект, исправляй выбранное решение; не маскируй исправление созданием альтернативной концепции.
