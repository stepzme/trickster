# End-to-end проверка процесса

## Цель

Проверить готовый пользовательский путь: установку компактного workflow, выбор по GitHub-каталогу, сохранение ровно одного локального пакета, переносимую оркестрацию ролей, реализацию, независимую приёмку, app icon, ASO screenshots и финальную очистку после подтверждения пользователя.

## 1. Подготовка

Установить текущий npm-пакет через `npx @sgx22/trickster init --harness <codex|generic>` в отдельный чистый тестовый проект. Убедиться, что выбранный harness читает инструкции Trickster, а `trickster/styles/` не установлен.

До задачи рабочий пакет в `trickster/design/` может отсутствовать: shortlist и выбор относятся к этапу 2. Подготовить Xcode, основной и компактный Simulator, взаимодействие с UI и просмотр изображений. В новой сессии проверить adapter, delegated mode либо последовательный fallback.

## 2. Тестовое задание

Использовать продукт с достаточно ясной основной задачей, но без готового выбранного дизайн-пакета или app icon. Для нового проекта обеспечить доступ к raw-файлам репозитория Trickster на GitHub.

## 3. Обязательные наблюдения

Проверить, что мастер и исполнители ролей:

1. прочитали активный adapter и исполняли role contracts в delegated mode либо явно выбранном `sequential fallback`;
2. определили scope и не добавили незапрошенные backend или integration-функции;
3. загрузили `styles/catalog.json` с GitHub, выбрали по метаданным не более трёх кандидатов и загрузили документы только этих кандидатов;
4. остановились до выбора пользователем ровно одного `appId`;
5. после выбора сохранили в `trickster/design/` только один цельный пакет и создали product contract;
6. все последующие роли читали стиль только из `trickster/design/`, не из GitHub и не из run artifacts;
7. implementation-owner единолично владел app code и реализовал один дизайн без смешивания пакетов;
8. visual-producer просмотрел Logoinspo-иконки и создал одну концепцию;
9. acceptance-reviewer независимо собрал, установил и проверил финальное приложение, не исправляя код;
10. мастер вернул конкретные дефекты implementation-owner и сам проверил итоговый handoff;
11. visual-producer после ACCEPTED создал один ASO-комплект из экранов финальной сборки;
12. мастер получил явное подтверждение пользователя только после APP ACCEPTED и ASO, затем очистил временные загрузки и build artifacts;
13. мастер выдал раздельные статусы приложения, app icon и ASO.

## 4. Негативные проверки

- Выбрать два пакета и убедиться, что мастер отклоняет объединение и просит оставить один.
- Отклонить весь shortlist и убедиться, что новый shortlist строится заново по каталогу.
- Сделать GitHub недоступным в новом проекте и убедиться, что UI-работа останавливается с конкретной недоступной ссылкой.
- Повторить тот же сценарий в проекте с полным `trickster/design/` и убедиться, что сохранённый пакет используется без сети.
- Проверить, что повторный `init` не удаляет выбранный рабочий пакет или артефакты.
- Убедиться, что ASO не показывает отсутствующие функции.
- Не подтверждать итог пользователем и убедиться, что очистка не запускается.
- Сделать делегирование недоступным и убедиться, что мастер выполняет роли последовательно и помечает режим как `sequential fallback`.
- Убедиться, что два исполнителя не записывают одновременно Xcode project, asset catalog, product.md или review.md.

## 5. Проверка поставки

Проверить содержимое `npm pack --dry-run`: установочный комплект содержит workflow, role contracts, adapters и templates, но не содержит `styles/`.

Проверить `styles/catalog.json` в репозитории: каждая запись содержит непустые `appId`, `name`, `url` и `category`, а соответствующие `ui.md` и `ux.md` существуют. Installer не создаёт `trickster/styles/` и при повторном запуске сохраняет существующий `trickster/design/`.

После финализации проверить, что временный каталог текущего run-id и записанные build artifacts удалены, а проект, `trickster/design/`, review/evidence, app icon и ASO сохранены.

## Условия перехода к релизу

Installer воспроизводимо создаёт компактный комплект без библиотеки стилей; новый запуск видит актуальный GitHub-каталог; shortlist ограничен тремя кандидатами; пользователь выбирает ровно один пакет; все роли после выбора используют его локальную копию; пакеты не смешиваются; scope не оказывается случайно минимальным; reviewer независимо проверяет сборку, когда harness это позволяет; app icon и ASO основаны на реальных источниках; очистка выполняется только после явного подтверждения пользователя.
