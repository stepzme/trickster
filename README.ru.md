# Trickster

Trickster — проектный процесс создания нативных iOS-приложений с AI-ролями. Главный принцип: сначала утвердить продукт, затем доказать дизайн на реально запущенном MVP и только потом развивать эту же сборку проверяемыми блоками.

## Установка

Запусти из существующего Git- или Xcode-проекта:

```sh
npx @sgx22/trickster init
```

Глобальная установка не поддерживается. `trickster doctor` проверяет локальный комплект.

## Пять стадий

| Стадия | Владелец | Результат |
|---|---|---|
| Research | Product Researcher | Полное описание продукта со всеми 11 iOS capabilities и явным подтверждением пользователя |
| Planning | Product Researcher | Утверждённый дизайн-MVP и упорядоченные блоки Full Scope |
| Design | Designer | Утверждённые референсы и реально запущенный, утверждённый пользователем MVP |
| Dev | Implementation Owner | Full Scope, реализованный и подтверждённый крупными блоками |
| Publish | Acceptance Reviewer | Независимая финальная проверка, итоговые визуальные материалы и контролируемая очистка |

Master координирует четыре специализированные роли и один общается с пользователем. После Research Planning и подбор референсов могут идти параллельно; владельцем кода в каждый момент остаётся одна роль.

## Дизайн

Designer выбирает до трёх приложений из базы реальных iOS-продуктов и предлагает один источник для UI и опциональный источник для illustrations. `ui.md` отвечает за внешний вид, `illustrations.md` — за изображения. Навигация и взаимодействие берутся из утверждённых Research и Planning и общих правил workflow, а не копируются из приложения-референса.

Утверждённые документы копируются без переписывания. Trickster не создаёт обобщённый проектный `ui.md`, composition-отчёт или provenance-слой. Дизайн подтверждается по работающему MVP в Simulator. Успешная сборка с типовыми карточками, default controls или пропущенной графикой не считается готовым дизайном.

## Обязательные capabilities

Порядок фиксирован:

1. Bluetooth
2. Скачивание фото
3. Добавление фото
4. Использование камеры
5. Face ID
6. Доступ к микрофону
7. Доступ к распознаванию речи
8. Доступ к контактам
9. Доступ к календарю
10. Доступ к геолокации
11. CallKit

Первые десять используют настоящий системный запрос доступа или authentication challenge. Мокать можно Bluetooth peripherals/data, обработку записи микрофона и результат распознавания речи. Сохранение фото, выбор фото с устройства, использование снимка камеры, Face ID, Contacts, Calendar и Location выполняются реально. У CallKit нет permission prompt, поэтому для него действует единственное честное исключение без выдуманного звонка.

## Структура

```text
trickster/
├── AGENTS.md
├── HARNESS
├── adapters/
├── roles/
├── workflow/
├── templates/
├── design/
└── artifacts/
```

Полная база стилей не входит в npm-пакет: Designer загружает только документы выбранного shortlist.

Требуются macOS, Xcode, iOS Simulator, физический iPhone для недоступных в Simulator финальных проверок, Node.js 20+ и agent harness, умеющий загрузить инструкции и работать с инструментами проекта.
